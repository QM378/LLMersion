# 对话练习（v2 预览）

用嘴说英语，全程本地。老师说的话有字幕，你说的话实时出字，说完立刻告诉你哪里错了、为什么错。

```
麦克风 ──► Whisper（本地 STT）──┬──► gemma 对话 ──► Kokoro 朗读 + 字幕
                                ├──► gemma 纠错（并行）
                                └──► wav2vec2 音素对齐（并行）
                                        ▲
                                你的生词本（三条都吃它）
```

---

## 跑起来

阅读器照常开着，另开一个终端：

```bash
python -m talk.main
```

浏览器打开 `http://127.0.0.1:8849/talk/`，点**弹出为浮动窗口**。

先看界面、不加载任何模型：

```bash
python -m talk.main dev
```

### 装什么

| 组件 | 你已经有了吗 |
|---|---|
| 对话和纠错模型 | 有 — 阅读器写作批改用的那个 `gemma3:4b` |
| 朗读 | 有 — Kokoro，阅读器开着时**直接借用**，不再加载一份 |
| 发音评分 | 有 — wav2vec2，同上 |
| 语音识别 | **唯一的新东西** |

识别有三条路，装了哪条走哪条。**Windows + NVIDIA 什么都别装**：项目为了翻译和发音评分已经装了
`transformers` + `torch`，会用它加载 `openai/whisper-base.en`（约 145 MB，首次自动下载），
5090 上一轮识别 0.2 秒左右。

**Mac 上装 `faster-whisper`**：CTranslate2 走 CPU int8，不碰 Metal，比 transformers 那条路稳。

```bash
pip install faster-whisper     # Mac 推荐，Windows 不必
```

口音重或环境吵，`PR_STT_MODEL=small.en`，约 3 倍开销，明显更准。

## 三种起点

开窗先选一个，都可以随时用标题栏的**换话题**换掉。

**自由说** —— 没有题目，跟着聊。默认就是这个。

**指定话题** —— 打一行字，比如 `why my experiment keeps failing`。老师围着它转，不会自己跑题。

**聊这篇文档** —— 从你在阅读器里读到的那一段开始，只谈那附近**写着的**东西。你说错了它会指出
段落里哪句话不是这么说的。这是别的口语产品做不到的：它们没有你的文档。

三种模式共用同一套东西——老师都会刻意用你生词本里的词，你说的每句都过发音评分和语法纠错。
文档只是话题来源，不是使用前提。

## 窗口怎么读

```
┌──────────────────────────┬───────────────────────────┐
│ 老师              ▶再听  │ 你说的                    │
│                          │                           │
│ 当前这句（大字，字幕跟着 │ 刚说完的一句              │
│ 声音一句一句变亮）       │ [发音 78] [用上 2 个生词] │
│ ─────────────────        │ ─────────────────         │
│ 上一轮说过的（点一下重听）│ 说话时这里实时出字        │
│                          ├───────────────────────────┤
│                          │ 纠正                      │
│                          │ ~~原句~~                  │
│                          │ 改过的句子（改动处高亮）  │
│                          │ │ 中文解释为什么这么改    │
│                          │ 音：ð→s                  │
└──────────────────────────┴───────────────────────────┘
```

左边全是老师：当前这句大字显示，**字幕跟着声音一句一句变亮**——用的是阅读器那套从波形恢复
句子边界的机制，不是按比例瞎猜。说过的话往下沉，点一下重听。

右边全是你：上面是你说过的话，下面是纠正。**纠正不打断对话**，它在旁边攒着。
说得对的时候它会直说"这句没问题"，不会为了有话说而挑毛病。

### 键位

| 键 | 做什么 |
|---|---|
| 按住 `Space` | 说话，松开发送。按下的瞬间老师的声音就停了 |
| `Esc` | 打断老师；正在录音时是取消这一句 |
| 点麦克风 | 按一次开始，再按一次结束（不想按住的时候） |
| 打字回车 | 不方便出声时的备用通道，一样走完整个对话、纠错 |

**打断是按键打断，不是声音打断。** 没有 VAD、没有插话检测——你按下空格或 Esc，声音立刻停，
你开始说。这是有意的：声音打断要处理回声、要判断你是在说话还是在咳嗽，复杂度不成比例。

### 底下那条生词带

窗口唯一的花活，也是它存在的理由：老师用到你的某个词，描边变黄；**你自己把它说出口，
才被荧光笔整条刷满**。策展让你重新遇到 → 写作让你写 → 这里让你说，第三条通道，而且可数。

## 调

| 变量 | 默认 | 作用 |
|---|---|---|
| `PR_TALK_PORT` | `8849` | 端口 |
| `PR_STT` | `auto` | `faster-whisper` / `transformers` / `openai-whisper` |
| `PR_STT_MODEL` | `base.en` | `small.en`、`medium.en`，或任意 HF 名字 |
| `PR_TALK_MODEL` | 跟随 `PR_LLM_MODEL` | 对话和纠错用的 Ollama 模型 |
| `PR_TALK_LEVEL` | `B1` | 老师说话的 CEFR 难度 |
| `PR_TALK_COACH` | `1` | `0` 关掉纠错那一路 |
| `PR_TALK_INTERIM` | `1` | `0` 关掉说话时实时出字 |
| `PR_TALK_SCORE` | `1` | `0` 关掉顺带发音评分 |
| `PR_TALK_PASSAGE` | `700` | 文档模式送进上下文的词数 |
| `PR_TALK_WORDS` | `12` | 每轮盯着的生词个数 |
| `PR_READER_URL` | `http://127.0.0.1:8848` | 阅读器在哪 |

四个开关在窗口右上角的齿轮里也能直接点。

阅读器**没开**也能用：朗读和评分会在本进程里自己加载一份。开着更省内存，这是默认路径——
启动横幅最后一行写着 `sharing its voice and scorer` 才说明借上了。

## 延迟

一轮的构成：识别 → 然后**对话、纠错、发音评分三件事同时跑**，取最慢的那个，不是三个相加。

5090 + `gemma3:4b` + `base.en` 大约 1.5–2.5 秒。窗口右下角每轮都报实测秒数。

纠错是**单独一次 LLM 调用**，不是塞进回复里的一个字段。对话和挑错是两件事，4B 一次做一件明显更好；
代价是如果你的 Ollama 不肯并发（`OLLAMA_NUM_PARALLEL=1`），这一轮会变成两次调用相加。
真觉得慢就 `PR_TALK_COACH=0`。

说话时的实时出字是**每 1.6 秒把已录到的音频重新识别一遍**，不是流式识别。GPU 上几乎不要钱，
笔记本 CPU 上会有点吃力，那就关掉。

## 已经合进阅读器了

工具栏上有个**对话**按钮，点开就是这个浮动窗口，浮在文档上面，不切走、不挡阅读。
再点一下收起，**会话留着**——回来还是刚才那段对话。

合进去之后多做两件独立窗口做不到的事：

- **跟着朗读头走**。文档模式下你继续往下听，它每几秒把话题重新锚定到你现在读到的段落，
  不用重开会话。
- **说话时阅读器自动停下**。你按住空格的瞬间，正在朗读的段落暂停，不跟你抢声音。

也不必用按钮：`python -m talk.main` 照旧能单独开一个窗口。

### 它是怎么接进去的

`server/main.py` 里一段 try 块，`web/index.html` 底部一段脚本。两处都是**可选加载**：

- `talk/` 文件夹不在，或者它自己的依赖缺了 → 阅读器照常启动，按钮自动隐藏，
  启动横幅写 `talk  not installed`
- `panel.js` 只在你**第一次点按钮**时才下载。从不说话的人一个字节都不用付

**想撤掉这个功能，删掉 `talk/` 文件夹就行**，别的什么都不用动。

对话记录写在**单独的** `talk.db`，不动 `reader.db`。

## 诚实的边界

**发音分拿你自己的转写当参考。** Whisper 听出你说了什么 → Kokoro 读一遍 → 两段音频过同一个音素模型
→ 编辑距离对齐。这能抓**发音走样**，抓不住**整词读错**：如果一个词你读得太离谱、Whisper 直接听成了
另一个词，参考也就变成那个词，你反而分高。闪卡里的单词评分没这个问题（目标词已知），
自由说话的代价就在这儿。

**参考音是合成的美音，所以口音会被算成错误。** 参考里 "what is" 的 t 是闪音 ɾ，你读干净的 /t/
就会被标成替换——你没错，是它在扣你"不够美国"的分。现在有一层保守的同位音折叠：去掉长音符和重音符，
再把 {ɾ,t,d}、{ɹ,r,ɻ}、{ə,ɐ,ʌ,ɜ}、{ɪ,i}、{ʊ,u}、{x,h} 各自并成一类，同类之间不算错。
每一对都是真同位音或记号差异，不是英语需要区分的对立——但**折叠只是让分数少骗你，不等于分数准了**。

**纠错基于转写，不是基于你的声音。** Whisper 会顺手把语法补齐、把"呃"删掉，所以有些口误在到达
纠错模型之前就消失了。看到的错误都是真的，但**没看到的不代表没有**。

**老师能力上限就是 4B 的上限。** 偶尔重复问题、偶尔把生词硬塞进不合适的位置。
`PR_TALK_MODEL=gemma3:27b` 明显更好，5090 跑得动。

**一轮一轮来。** 打断靠按键，不能一边听一边说。真正的全双工要流式识别 + VAD + 回声消除，
是另一块工程。

**麦克风需要 localhost 或 https。** 远程访问用 SSH 端口转发，浏览器才肯给权限。见 `docs/DEPLOY.md`。

**还没做**：词级卡拉 OK 高亮（需要词级时间戳）、间隔重复调度、对话中途查词。
